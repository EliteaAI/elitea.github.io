# Highlighting (from styleguide: wording and formatting)

Highlight only words and the punctuation between them. Keep adjacent punctuation plain.

## Bold
- UI elements with a visible label: buttons, checkboxes, settings, menus, pages, tabs: "Select **Save**." "In the **Name** tab, …"
- Navigation paths: "In **One** > **Two**, find …"
- Run-in headings and notices: **Note**, **Warning**, **Caution**.

## Italic
- Terms and their definitions; terms and words used as words ("Use *word* to …").
- File names, file name extensions and paths.
- Titles of books, movies, web series and other full-length works.
- Mathematical variables and version variables.
- Placeholder text shown inside a UI field: "In the field *Add people from the team project*, …" (interim rule, user decision 2026-11-17).

## Inline code
Code font for things that relate to code, in ordinary sentences:
- Text a user enters in the UI; short error messages; command output.
- Configuration parameters, keywords and code; attribute names and values; constant values; Boolean values.
- Class, method, function, element (HTML, XML) and package names; namespace aliases; language keywords.
- Command-line utility names; environment variable names; folders and directories.
- Database elements (row and column names); IAM role names; DNS record types.
- HTTP verbs, status codes and content-type values; IP addresses; port numbers; query parameter names and values.
- Placeholder variables; strings used in commands and code (URLs, domain names); email addresses as input or output.

## Code blocks
- Use for CLI commands and code samples, in Mintlify fenced syntax. Introduce each with a sentence or paragraph.
- Follow the relevant coding-style guide.

## Other
- Underline only for link text. UPPERCASE only in official names, abbreviations or all-caps code.
- UI messages that are not errors (for example "Access updated") have no rule yet: report how you formatted them.
