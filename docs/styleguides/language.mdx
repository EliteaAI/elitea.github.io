# Language guide

## General

- Texts must be clear, focused, precise, direct, and approachable.
- Write factually and objectively. State only things that are verified and verifiable.
- Be active. Give direct instructions.
- Write from the customer's perspective. Focus on functionality and benefits to the customer.
- Be specific. Focus on facts and achievable goals.
- Write in US English with US grammar.
- Use simple words and shorter sentences. Use shorter paragraphs (up to five sentences long).
- Do not use ambiguous words.
- Use consistent terminology, consistent sentences and sentence structures, and consistent formatting.
- No plagiarism. Cite directly with links or rephrase with references.

## Voice and tone

- Be friendly and respectful.
- Be natural and approachable.
- Avoid placeholder phrases like "please note" and "at this time."

## Grammar

1. Prefer the active voice over the passive. Use the passive voice only when you need to focus on who receives the action rather than on who or what is performing it.
2. Use present tense. Use future tense for actions that will occur in the future.
3. Prefer positive constructions over negative ones.
4. Pronouns:
   1. Use you/your and speak directly to the user.
   2. Use they (their, them) to refer to a generic person whose gender is unknown or irrelevant.
   3. Use it/its to speak about an organization, company, business, or individual client (unless you refer to clients in the plural).
   4. Use I only in FAQs.
   5. Check that a pronoun refers to the correct word.
5. Do not use contractions (don't, 's, 'll).
6. Do not use possessives ('s) for proper nouns, like organization or product names (ELITEA's).
7. Plurals:
   1. Use regular plural forms.
   2. Avoid using 's to form the plural of abbreviations (including acronyms and initialisms): APIs, not API's.
   3. Do not make an abbreviation plural when it is a unit with a number (64 GB, not 64 GBs).
   4. Do not put optional plurals in parentheses. Instead, choose what is more appropriate for your text. If necessary, use the words "one or more."
8. Avoid phrasal verbs.
9. Abbreviations (including acronyms and initialisms):
   1. If you use abbreviations, spell them out (followed by the abbreviation in parentheses) on first use on a page. Do not spell it out more than once on a page.
   2. For countries commonly named by their acronyms and initialisms, use these without spelling out the full name.
   3. Do not make acronyms and initialisms plural.
   4. Do not make acronyms and initialisms possessive. If impossible, spell out the words.
10. Use parallel structures for similar things:
    1. Use the same structure and tense for each list item.
11. In sentences, write location, reason, condition, and then action.

## Punctuation

1. Omit the serial comma in a simple series (no Oxford commas).
2. Lists:
   1. Use the same punctuation for all list items.
   2. Do not use a period if the item is not a complete sentence.
   3. Use a period if the item is a complete sentence.
   4. Use periods or appropriate punctuation for every sentence when items have more than one sentence.
3. Use double quotation marks ("") for quoted text and keep all punctuation within the quotation marks. For quotes within quotes, use single quotation marks ('').
4. Country acronyms:
   1. Use periods for acronyms of two letters (U.S., U.K.).
   2. Do not use periods for acronyms of three or more letters (USA, UAE).
5. Do not use en dashes (–). Use hyphens (-) in words and em dashes (—) between them.
6. Do not put a space before or after em dashes (—).
7. Do not use ellipses (...).
8. Use parentheses sparingly and keep them short. If text in parentheses is long, reorganize it into two sentences.
9. Avoid question marks. Do not use exclamation marks.
10. Use slashes (/) only in URLs. Avoid them in other cases.

## Capitalization

1. When you refer to any product, use the official capitalization defined by its producer.
2. When you refer to specific UI text — a button label, page, tab, or menu item — use the same capitalization that appears in the UI.
3. Use lowercase for glossary and index terms unless the term is a proper noun.
4. Use sentence case for all elements in a table: contents, headings, labels, and captions, if any.

## Navigation

- Be brief and specific. Do not explain obvious things.
- Write location, then action. Write reason, then action.
- Do not use directional language. Say exactly what to do or where to go.

| Worse | Better |
| --- | --- |
| Select **Start** to run the wizard. | Select **Start**. |
| Select **Project Context** in **Settings**. | In **Settings**, select **Project Context**. |
| Go to **Analytics** to view the list of top 5 AI adopters. | To view the list of top 5 AI adopters, go to **Analytics**. |
| Select the button below. | Select **Publish**. |

## Sensitive data

1. **Do not include real usernames or email addresses in the documentation and visual aids (images, GIFs, videos).**
2. Use diverse and non-gendered names with common surnames. Use fake email addresses ending in `@email.com` or `@example.com`.
3. If not possible, blur the personal data.
4. Use fake website names like `example.com`.
5. Use fake tokens:

| Token type | Fake token |
| --- | --- |
| Personal access token | `<your_app_token>` like `<your_jira_token>`, `<your_confluence_token>` |

## Accessible language

- Avoid unnecessary font formatting.
- Do not force line breaks (hard returns) in sentences and paragraphs.
- Avoid exclamation marks, question marks, and semicolons.
- Break up very long paragraphs.
- Use shorter sentences.
- State important information at the beginning of the section or paragraph (first-sentence rule).
- Do not use double negatives and exceptions for exceptions.
- Add alternative text to images.
- Use tables sparingly because they are challenging for screen readers. Pre-announce tables.
- Do not use color, size, location, or other visual cues as the primary source of information.

## Inclusive/bias-free language

1. Use they (their, them) to refer to a generic person whose gender is unknown or irrelevant.
2. Avoid gendered language.
3. Avoid figurative language. Do not use idioms, jargon, metaphors, etc.
4. Avoid ableist language (words and phrases like crazy, insane, blind, cripple, dumb, etc.).
5. Be culturally neutral. Avoid references to specific holidays, cultural practices, and figures of speech.
6. Use diverse and non-gendered names and surnames.

## Localization

**Avoid**

1. Phrases that hide the subject, like "there is" and "there are."
2. Ambiguous pronouns like "it."
3. Multiple-meaning words in cases where their exact meaning is not clear (better, always).
4. Words that can be confused with one another.
5. Culture-specific references.
6. Long noun strings (three or more nouns in a row, without possessive cases or of-phrases).
7. Avoid using list items to complete an introductory phrase. This format can be difficult to localize into languages that use different sentence structures:

| Worse | Better |
| --- | --- |
| You can get the license key by:<br/>- Copying it from the email.<br/>- Downloading the file. | You can get the license key by one of these methods:<br/>- Copy the license key from the email.<br/>- Download the file. |

**Use**

1. Sentences with explicit subjects.
2. Single-meaning (monosemantic) words.
