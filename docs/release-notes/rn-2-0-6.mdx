---
title: "Release Notes - 2.0.6"
---

ELITEA 2.0.6 focuses on organizing, protecting and sharing your work. This release introduces agent evaluation, project backup and restore, chat-built Skills and Project Context with a new Ask User tool, external conversation sharing, AI follow-up suggestions and side-by-side version comparison. It also redesigns the indexing, toolkit and testing experience, and improves navigation, version selection, Canvas and catalog discoverability.

* **Release version**: 2.0.6
* **Released on**: September 13, 2026
* **Access**: [ELITEA Platform](https://next.elitea.ai)

## New Features

### Agent Evaluation (Beta)

You can now evaluate chat and task-automation agents from a new **Evaluation** tab on the agent editor, scoring runs against configurable dimensions and comparing results across datasets and runs.

<Note>
Agent Evaluation is a Beta feature. Supported engines and metrics may change.
</Note>

* Define evaluation dimensions using an AI-judge, Human or Code engine, each with its own evidence scope, weight, target and polarity.
* Group dimensions and code validations into a suite bound to a specific agent version.
* Run a suite as an offline batch over a dataset or on demand against a single conversation.
* Review the results with native and normalized scores, and add inline human scores that trigger automatic re-aggregation.
* Rely on an append-only human-score audit trail and role-gated access.

**Benefits:** Repeatable, measurable agent testing that surfaces regressions and quality issues before they reach users.

Details: [Agents](../menus/agents).

### Project Back up & Restore

You can now back up your project's data and restore it for both team and private projects.

* Create an encrypted backup file covering agents, pipelines, toolkits, MCP servers and skills to restore them, if needed. Credentials, tokens and other secrets are excluded from the backup.
* Preview a restore with a dry run before applying it.
* Choose whether the restored entities replace the existing project data or merge with them.
* Platform Admins can take a full, raw database-level backup or restore of a project from the Admin panel.

**Benefits:** Faster recovery of the project data without compromizing its security.

Details: [General Settings](../menus/settings/general#back-up-restore), [Back Up & Restore Project Data](../how-tos/entity-management/backup.mdx).

### Clarifying Questions and Follow-up Suggestions in Chat

You can now communicate with chat more effectively and get more correct responces with a new chat module and an additional clickable AI-generated follow-up suggestions.

* Enable the **Ask User** module so the assistant can pause mid-run and ask structured clarifying questions instead of guessing.
* Answer clarifying questions one at a time.
* Rely on **Ask User** failing safely in headless or API-only runs, returning a default answer instead of hanging.
* Select a suggestion chip to insert it into the chat input as editable text or skip the suggestion.
* Keep suggestions private and non-persistent.

**Benefits:** fewer wrong assumptions from agents when requirements are unclear, faster follow-up messages with less typing.

Details: [Chat](../menus/chat), [Ask User](???).

### Skill and Project Context Buiders

You can now build skills and project context directly from the chat, using two new chat modules.

* Turn on the new **Skills Builder** or **Project Context Builder** modules — each toggled independently.
* Open a generated skill or project context from a chip/link in the chat response.
* Keep the creation of skills and project contexts scoped to the current project, even when you have access to other projects.

**Benefits:** Faster and easier creation.

Details: [Skill Builder](???), [Project Context Builder](???).

### Folders for Project Entities

You can now group Agents, Pipelines, Toolkits & Indexes, MCPs and Credentials into folders.

* Create a folder from the **Folders** panel, from a card, or directly while moving an entity into a new folder.
* Move entities to or between folders without affecting their configurations, versions or permissions — folder organization is never a mechanism for granting access or changing the entity.
* Rename or delete folders at any time — deleting a folder leaving its entities untouched.
* Keep search global across all folders and unfiled entities.

**Benefits:** Easier organization and navigation.

Details: [Agents](../menus/agents), [Pipelines](../menus/pipelines), [Toolkits](../menus/toolkits#organize-toolkits-with-folders), [MCPs](../menus/mcps), [Credentials](../menus/credentials).

### Folder-Level Permissions for Project Entities

You can now control who can view or modify content in team folders of Agents, Pipelines, Toolkits & Indexes, MCPs and Credentials.

* Manage access per folder by assigning clear folder permission levels.
* Apply a folder exception to every entity currently inside it, including indexes.
* Add, search, edit and remove exceptions for one or multiple users at once, with a clear **Exceptions** count.
* Restore a user to normal role-based access at any time.
* Enforce restrictions consistently across the UI, REST and RPC paths, including list, search, move, copy, fork and export operations, so direct API access cannot bypass a folder restriction.

**Benefits:** Better control over sensitive entities without changing project-wide roles.

Details: [Agents](../menus/agents), [Pipelines](../menus/pipelines), [Toolkits](../menus/toolkits), [Credentials](../menus/credentials).

### Sharing Conversations with External Users

You can now share chat conversations with people outside ELITEA through a secure, read-only public link.

* Use a secure, read-only public link to share your conversation.
* Choose what to share before generating the link.
* Set the expiration period and (optional) protect the link with a password.
* Share the link with recipients even without an ELITEA account — they can only view the shared content, not modify it or reply.

**Benefits:** A simple, controlled way to share your conversations to people outside your organization.

Details: [Chat](../menus/chat).

### Creating New Chats Inside a Folder

You can now start new conversations directly in the chat folder instead creating it elsewhere and moving to the folder manually.

**Benefits:** Faster chat organization.

Details: [Chat](../menus/chat).

### Default Modules for Chats and Agents

You can now configure default modules for chats and agents in the project settings.

* Specify what modules are turned on by default for your project by a set of separate toggles. All toggles are disabled by default for new projects.
* Apply project-level defaults only to newly created chats and agents.
* Turn on or off modules when using chats and agents (if you have the necessary permission).

**Benefits:** Consistent, predictable default behavior for new chats and agents.

Details: [General Settings](../menus/settings/general#default-modules).

### Comparing Agent and Skill Versions

You can now compare two saved versions of an agent or skill in a designated comparison modal.

<Note>
Version editing is available only to users with edit permissions and only when at least two versions exist.
</Note>

* Use a side-by-side comparison modal with highlighted differences and available per-field copy actions.
* See all the differences, including unsaved edits made during the comparison.
* Edit and save versions independently. Saving overwrites the existing version without creating a new one.

**Benefits:** Faster, more accurate version review for agents and skills.

Details: [Agents](../menus/agents), [Skills](../menus/skills).

### JavaScript Execution in HTML Preview

You can now run JavaScript in the HTML preview frame, in both Artifacts and Chat.

* Execute JS code embedded in `.html` files when rendered in the **Preview** mode, in both the Artifacts canvas and Chat.
* Build more dynamic, interactive HTML content instead of static markup only.
* Rely on the existing sandboxed preview isolation that keeps rendered content from accessing ELITEA session data, cookies, local storage, or the parent page.

**Benefits:** Richer, more interactive HTML previews without leaving Artifacts or Chat.

Details: [Artifacts](../menus/artifacts), [Chat](../menus/chat).

## Changed Features

### Indexing and Reindexing Enhancements & Redesign

You can now create, configure, monitor and search indexes through fully redesigned Toolkit and Index pages, with clearer information, safer reindexing and consistent run history across the whole indexing experience.

* Create a new index from a dedicated **New Index** page, then land on the Index details page with **Activity** selected once indexing starts.
* Navigate a redesigned two-column Index details page — index summary, item counts and schedule on the left, **Configuration** and **Activity** tabs on the right — with **Search**, **Run History** and **Delete Index** actions, and status-aware **Stop**/**Reindex** actions in each indexing state.
* Run searches against an index from a dedicated **Search** page with its own Settings and Results panels, limited to the search tools that index actually supports.
* See enabled/total tool and index counts, and warning/error status icons, in the Toolkit details page's **Tools** and **Indexes** section headers, with **Configuration** grouping secondary fields behind **Show more** and Form/Raw JSON switched to icon controls.
* Keep an existing index searchable throughout a reindex — a failed manual or scheduled reindex no longer breaks or empties the active index, which is only replaced once the new version completes successfully.
* Save configuration changes to an index with **Save** alone, without triggering a reindex, or use **Save & Reindex** to also reindex with the newly saved settings; scheduled reindexing always uses the latest saved configuration.
* Read readable, source-specific indexing and reindexing summaries — successfully indexed, skipped, not indexed and failed counts with reasons, using source-appropriate item names — in place of raw JSON or chunk counts, in both Toolkit and Index History.
* Get consistent Run History across toolkits and indexes, with the same Date, Event and Duration columns, a **Share link** action scoped to users with access to that index, and correctly labeled search-tool events.

**Benefits:** Clearer indexing status at every step, safer reindexing that never breaks a working index, and consistent, understandable history across toolkits and indexes.

Details: [Toolkits](../menus/toolkits), [Indexing Overview](../how-tos/indexing/indexing-overview), [Create & Use Indexes](../how-tos/indexing/using-indexes-tab-interface.mdx).

### Redesigned Toolkit Tools Section

You can now configure a toolkit's tools through a redesigned **Tools** section that groups, searches and flags tools by risk, on both the create and edit forms.

* Browse tools grouped by operation type — **Read**, **Create & update**, **Delete** and **Execute** — each with a risk badge, an info tooltip explaining the group, and a selected/total tool count, in a fixed order with empty groups hidden.
* Search tools by display name or technical name without changing your current selections, and see groups with no matches hidden.
* Select or deselect every tool in a group at once from the group header.
* Use **Keep read-only only** to deselect every selected Create & update, Delete and Execute tool in one click, while leaving your Read selections untouched — nothing is saved automatically.
* Review previously selected tools that are no longer available in a separate **Unavailable** block above the grouped list.
* Turn on **Enable MCP access for selected tools** — the renamed MCP checkbox, now a toggle disabled by default for new toolkits and preserving existing values for toolkits you already created.

**Benefits:** Faster, safer tool configuration with clear visibility into which tools read, write, delete or execute unrestricted actions.

Details: [Toolkits](../menus/toolkits).

### Test Toolkits from a Dedicated Page

You can now test a toolkit's tools from a dedicated **Test** page instead of an embedded panel on the Toolkit details page.

* Select **Test** from the Toolkit action bar, next to **Run History**, to open the Toolkit Test page in the same browser tab.
* Navigate back to the Toolkit details page at any time using the **Toolkits / [Toolkit name] / Test** breadcrumb trail.
* Select a tool, search among available tools, configure its parameters and choose a model where applicable, from a dedicated **Test Settings** panel on the left.
* Run the selected tool and review its execution result, including existing copy actions, error display and loading states, in the **Results** panel on the right.

**Benefits:** More room to configure and review toolkit tests, without the Toolkit details page's configuration and indexes competing for space.

Details: [Toolkits](../menus/toolkits).

### UI Enhancements for Agents, Pipelines and Skills

You can now navigate and manage versions on Agent, Pipeline and Skill details pages more clearly, with breadcrumb navigation and a redesigned version selector.

* Navigate with breadcrumbs — **Agents / [Agent name]**, **Pipelines / [Pipeline name]**, **Skills / [Skill name]** — instead of a back button, with the entity-type link returning you to its list page.
* Search the version dropdown by version name or creator, and see each version listed with its name, creation timestamp and creator instead of a single combined line.
* Tell the currently loaded version apart from the default version — a checkmark and row highlight mark what's selected, an active pin marks the default, and the two states stay independent of each other.
* Keep versions sorted by creation date, newest first, regardless of search or which version is selected or default.
* Continue setting a version as default through the same **Set as default?** confirmation, now triggered from the redesigned pin action.

**Benefits:** Faster navigation and clearer version identification across Agents, Pipelines and Skills.

Details: [Agents](../menus/agents), [Pipelines](../menus/pipelines), [Skills](../menus/skills).

### Canvas Mode for Chat-Generated Entities

You can now review and edit an Agent, Pipeline, Skill or Project Context generated from Chat immediately in Canvas mode, without leaving the conversation.

* Have a newly generated Agent, Pipeline, Skill or Project Context open automatically in Canvas mode, with Chat still visible alongside it.
* See multiple items generated in the same response open as separate Canvas tabs, each showing the entity's name and type icon, and switch between tabs without losing unsaved edits.
* Reopen a generated entity's Canvas from its chip/link in the Chat response at any time after closing it.
* Save or discard changes and close a Canvas tab using the existing entity editor controls, with a warning before losing unsaved changes.
* Keep generated entities out of the Chat's participant list by default — add a generated Agent or Pipeline as a participant afterward through the existing participant-selection flow, while generated Skills and Project Context stay accessible only from their chip/link, never as participants.

**Benefits:** Faster review and editing of chat-generated entities, with no extra tabs or navigation needed.

Details: [Chat](../menus/chat).

### Catalog Item Counts and "New" Badges

You can now see how many Agents and Skills are available in the catalog at a glance, and spot recently added items without scanning the whole list.

* See a total count of visible Agents and Skills in the catalog header or section titles, updating in real time as you search or apply filters.
* Spot a **New** badge on any Agent or Skill catalog card added within the recency window, with the badge disappearing automatically once the item ages out of that window.
* Use the **New** quick filter in the catalog filter panel to show only recently added items.
* Rely on an admin-configurable recency window (default 14 days, 7–60 days range) that controls how long items are marked **New**.

**Benefits:** Faster sense of catalog breadth and easier discovery of new Agents and Skills without manually scanning the whole catalog.

Details: [Agents](../menus/agents), [Skills](../menus/skills).
