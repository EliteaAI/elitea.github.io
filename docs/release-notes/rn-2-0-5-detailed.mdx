## Release Overview

ELITEA 2.0.5 focuses on making ELITEA easier to configure, easier to scale, and easier to understand in day-to-day use. This release expands AI-assisted creation and editing, introduces stronger skill reuse and publishing workflows, adds new usage and analytics visibility, redesigns settings, sidebar, and indexing experiences, and improves toolkit, chat, artifact, and platform behavior across both private and team projects.

## Information

* **Release Version**: 2.0.5
* **Released on**: 06-Aug-2026
* **Access**: [ELITEA Platform](https://next.elitea.ai)


## New Features

### Edit with AI for Agents, Skills, and Project Context

ELITEA now extends AI-assisted authoring beyond creation flows by adding **Edit with AI** for existing agents, skills, and project context, so users can describe desired changes in plain language, review AI-generated updates, and apply only the changes they want.

**What you can do now:**

* **Edit existing agents with AI assistance**: Open **Edit with AI** on an agent, describe what should improve, and review suggested updates for fields such as general details, instructions, user interaction, tools, and skills through a guided comparison flow.
* **Edit existing skills with the same AI-assisted pattern**: Request improvements to a skill's name, description, and instructions, then compare current and suggested values before applying the accepted result.
* **Edit project context with AI-generated revisions**: Use **Edit with AI** on Project Context to generate a suggested update for the Project Background field, compare it against the current content, refine the prompt if needed, and apply the revised version.
* **Review current versus suggested content before applying changes**: Work with side-by-side or step-based comparison flows that highlight differences and make it easier to understand what the AI is proposing.
* **Keep control over what gets applied**: Edit suggested text further, exclude unwanted suggestions where supported, or cancel the flow entirely without changing the current configuration.

**Benefits:** Faster iteration on existing assets, less manual rewriting, clearer review of AI-proposed changes, and a more consistent AI-assisted editing experience across core ELITEA entities.

For more information, see [Agents](../menus/agents), [Skills](../menus/skills), and [Project Context](../menus/settings/project-context).

### Skills Support Autonomous Invocation with Progressive Disclosure

ELITEA now advances the Skills feature beyond explicit `~skill-name` usage by allowing agents to work with attached skills more autonomously through progressive disclosure, reducing the need for users to know and invoke every skill manually.

**What you can do now:**

* **Let agents use attached skills more autonomously**: Give agents access to attached skill context so they can apply relevant skills without always requiring an explicit `~skill-name` token in the user message.
* **Keep skill usage scoped to what is attached**: Ensure agents only work with the skills attached to their own configuration rather than pulling from a broader global pool.
* **Support richer multi-skill behavior in one turn**: Allow multiple relevant skills to be applied within the same interaction when the task calls for them.
* **Improve visibility into skill usage during execution**: Surface loaded skill information more clearly in the runtime experience so users can better understand which skills were brought into the flow.
* **Lay the groundwork for smarter skill-driven orchestration**: Move Skills closer to an on-demand, progressive-disclosure model that better supports advanced agent behavior and future sub-agent skill handling.

**Benefits:** Less manual skill invocation, more natural use of attached expertise, better scalability for skill-driven agents, and a clearer path toward more autonomous agent behavior.

For more information, see [Skills](../menus/skills) and [Agents](../menus/agents).

### Skills Support Self-Service Publishing with Quality Validation

ELITEA now extends the Skills feature with self-service publishing, allowing users to publish reusable skills into a shared catalog through a guided flow backed by deterministic and AI-powered quality validation, while also preserving attached skills when publishing agents that depend on them.

**What you can do now:**

* **Publish skills through a guided self-service flow**: Use a structured publishing wizard for skills instead of relying on a placeholder or manual publishing path.
* **Validate skill quality before publishing**: Run deterministic and AI-assisted checks against skill name, description, instructions, icon, version name, and category before a skill becomes publicly discoverable.
* **Classify published skills with categories**: Assign skills to curated categories so published content is easier to browse and manage in the shared catalog.
* **Support multiple published versions of the same skill**: Publish and manage more than one version of a skill while keeping version naming and validation in the publishing flow.
* **Publish agents without losing their attached skills**: Keep skills attached to an agent when that agent is published, so the published agent continues to use the expected skill-backed behavior.
* **Use admin controls for governance and unpublishing**: Rely on platform-level controls for blocking publishing, managing validation rules and categories, and unpublishing skills when needed.

**Benefits:** Faster skill sharing, stronger publishing quality, better discoverability of reusable skills, safer publishing of skill-dependent agents, and clearer governance for public skill content across the platform.

For more information, see [Skills](../menus/skills) and [Agent HUB](../menus/agents-studio).

### Skills Are Easier to Reuse, Customize, and Scale Across Projects

ELITEA now expands the day-to-day usability of Skills by making them easier to fork between projects, personalize with custom icons, and author with longer instruction bodies.

**What you can do now:**

* **Fork a skill version directly to another project**: Copy a selected skill version into another project you can access without relying on a manual export-and-import workaround.
* **Fork agents together with their attached skills**: Preserve skill-backed behavior when moving agents across projects so the forked result stays closer to the original working setup.
* **Upload custom icons for skills**: Personalize skills with their own uploaded icons and see those icons reflected in skill cards, menus, and related skill-selection surfaces.
* **Write more complete skill instructions**: Use an increased instructions limit of up to 5,000 characters so skills can hold richer guidance, examples, and output expectations.
* **Improve skill discoverability and reuse across teams**: Work with skills that are easier to recognize visually, easier to move between projects, and easier to maintain as reusable building blocks.

**Benefits:** Better cross-project reuse of skills, clearer visual identification, more expressive skill definitions, and a smoother workflow for teams building and sharing reusable prompt assets.

For more information, see [Skills](../menus/skills) and [Agent HUB](../menus/agents-studio).

### Aha! Toolkit Adds Product Management Integration & Indexing Support

ELITEA now adds an **Aha!** toolkit under **Project Management**, so teams can connect Aha!, work with product-management records in agents, pipelines, and conversations, and index supported Aha! data for downstream AI use.

**What you can do now:**

* **Connect Aha! through native toolkit configuration**: Add **Aha!** as a toolkit in **Toolkits** > **Project Management**, configure it with an Aha! credential, and validate the connection with clear success or error feedback.
* **Use personal or project-scoped Aha! credentials**: Create **Aha!** credentials in **Credentials** > **Project Management** and use either personal credentials for individual access or project credentials for shared project use.
* **Work with Aha! records through dedicated toolkit tools**: Find projects, search and read records, analyze selected records, retrieve report data and metadata, manage supported records and reports, add comments, copy records, and create record links through the toolkit.

**Benefits:** Better access to product-management data, smoother Aha!-based agent and indexing workflows, clearer traceability for indexed records, and safer handling of Aha! authentication and API errors.

For more information, see [Toolkits](../menus/toolkits), [Credentials](../menus/credentials), and [Indexing](../how-tos/indexing/using-indexes-tab-interface.mdx).

### Artifacts Add Bucket-Level Access Management for Team Projects

ELITEA now adds bucket-level access management for **Artifacts** in Team projects, so authorized users can control who can view or modify content in a specific bucket through a redesigned **Manage access** experience.

**What you can do now:**

* **Manage access per bucket in Team projects**: Open **Manage access** for a selected bucket to control bucket-specific permissions without changing the existing behavior for Private or Public projects.
* **Assign clear bucket permission levels**: Set **No access**, **Read**, or **Read & Write** permissions for individual users so access to bucket content is easier to control.
* **Work with a redesigned Permission Exceptions view**: Use an updated access-management UI that presents assigned users as **Permission Exceptions**, with clearer terminology, improved empty states, and more consistent table behavior.
* **Add and edit access exceptions more efficiently**: Use redesigned add and edit flows with searchable user selection, permission assignment, bulk actions, and clearer single-user or multi-user update patterns.
* **Apply permissions to all content in the bucket**: Control access for the selected bucket and its nested folders and files through one bucket-level permission model.
* **Enforce restrictions beyond the UI**: Rely on the same bucket permissions across the ELITEA Artifacts API and S3-compatible routes so users cannot bypass access rules through direct requests.

**Benefits:** Better control over shared artifact content, clearer access-management workflows for Team projects, more consistent permission handling across interfaces, and safer protection of bucket data.

For more information, see [Artifacts](../menus/artifacts).

### Artifacts & Chat Canvas Add HTML and MDX Preview & Editing Support

ELITEA now expands file support in **Artifacts** and **Chat** canvas by adding preview and raw editing modes for HTML and MDX files, so users can review, edit, and save generated or uploaded content without leaving the platform.

**What you can do now:**

* **Open HTML and MDX files directly in canvas**: Work with supported `.html`, `.htm`, and `.mdx` files in **Artifacts** and open generated files from chat results without downloading them first.
* **Switch between Preview and Raw modes**: Use **Preview** to render supported HTML or MDX output and **Raw** to inspect or edit the source code with syntax highlighting.
* **Start in Preview mode by default**: Open HTML and MDX files in rendered view first, then move to **Raw** mode when you need to inspect or update the source.
* **Edit and save source files in place**: Update HTML or MDX content in **Raw** mode and save changes back to the same file in the same Artifacts bucket and path, with existing save, discard, and unsaved-changes behavior.
* **Open generated files from chat with the same workflow**: Use generated artifact items in chat to open HTML or MDX files in canvas, preview them immediately, and edit them when you have write access.
* **Use safer preview isolation for rendered content**: Rely on sandboxed preview behavior that helps prevent rendered HTML or MDX content from accessing ELITEA application context, session data, cookies, local storage, or the parent page.
* **Handle unsupported or unsafe MDX content more clearly**: Prevent unsafe MDX constructs from executing in preview and show a clear warning when a file contains unsupported or unsafe components.

**Benefits:** Better in-platform review of generated reports and documentation, faster editing workflows for HTML and MDX content, safer preview handling for rendered files, and less need to switch to external tools.

For more information, see [Artifacts](../menus/artifacts) and [Chat](../menus/chat).

## Changed Features

### Toolkits & Indexes Redesigns the Full Index Lifecycle Experience

The indexing experience has been redesigned across discovery, configuration, execution, scheduling, and history, with **Toolkits** renamed to **Toolkits & Indexes** to make index management easier to find and easier to use end to end.

**What you can do now:**

* **Discover index-capable toolkits more clearly**: Use the redesigned **Toolkits & Indexes** landing page to browse searchable toolkit cards and see which toolkits support indexing, including index counts where applicable.
* **Navigate toolkit and index views more consistently**: Work with clearer breadcrumb-based navigation between toolkit-level and index-level pages.
* **Create indexes through a dedicated configuration flow**: Open a dedicated new-index page from the toolkit details view, configure index parameters, validate required fields, and start indexing from one focused setup experience.
* **Manage existing indexes directly from toolkit and index pages**: Reindex or delete indexes from cards or details pages, with safer delete confirmation and support for editing index configuration through a safer reindex workflow.
* **Monitor runs with clearer status and history views**: Track in-progress and ready states, review indexed and skipped counts, open structured run history, and inspect activity and search settings from the redesigned index details page.
* **Configure recurring indexing more flexibly**: Set schedule rules through a redesigned scheduling flow with simple default frequency options or advanced cron input, plus human-readable schedule summaries.
* **Work with a more complete indexing workflow in one place**: Move from toolkit discovery to index creation, execution, search validation, scheduling, and history review through one more consistent interface.

**Benefits:** Better index discoverability, clearer lifecycle management, safer reindex and delete workflows, improved visibility into run outcomes, and a more consistent indexing experience across supported toolkits.

For more information, see [Toolkits](../menus/toolkits), [Indexing Overview](../how-tos/indexing/indexing-overview), and [Schedule Indexing](../how-tos/indexing/schedule-indexing).

### Index Configuration Changes Use a Safer Reindex Workflow

Index configuration updates are now handled through a safer reindex workflow, so users can change indexing-critical settings for an existing index without silently leaving the stored index out of sync with the saved configuration.

**What you can do now:**

* **Edit indexing-critical settings more safely**: Update existing index configuration values such as source settings, chunking parameters, filters, and other indexing-related options through a workflow that recognizes when a reindex is required.
* **Avoid silent configuration drift**: Prevent situations where toolkit settings change but the existing index still reflects older indexing parameters.
* **Use reindex as part of configuration updates**: Apply configuration changes through a safer reindex path instead of treating index-affecting edits as ordinary settings changes.
* **Reduce risk when reindexing after configuration changes**: Work with a safer update flow designed to protect the existing index if the new reindex operation does not complete successfully.
* **Keep index maintenance more predictable**: Make it clearer when configuration edits affect index quality or source coverage and require rebuilding the index.

**Benefits:** Better consistency between saved settings and actual index contents, safer maintenance of existing indexes, less risk during configuration changes, and clearer expectations when reindexing is required.

For more information, see [Indexing Overview](../how-tos/indexing/indexing-overview).

## Fixed Issues

* [#6057](https://github.com/EliteaAI/elitea_issues/issues/6057) **Continue now resumes truncated responses instead of generating a new one from scratch**: Clicking **Continue** now extends the previous incomplete response rather than replacing it with a separate fresh answer.
* [#5996](https://github.com/EliteaAI/elitea_issues/issues/5996) **GitLab toolkit initialization no longer fails on missing description values**: GitLab toolkit loading now handles missing values more safely instead of failing with a `TypeError` during initialization.
* [#5994](https://github.com/EliteaAI/elitea_issues/issues/5994) **GitLab root listing no longer requires a `path` value in the UI**: GitLab toolkit folder and file listing tools now treat `path` as optional in the UI, matching backend behavior for repository-root access.
* [#5894](https://github.com/EliteaAI/elitea_issues/issues/5894) **Remote MCP sessions no longer remain active after logout**: Logging out now invalidates the related Remote MCP session so subsequent requests require proper re-authentication.
* [#5823](https://github.com/EliteaAI/elitea_issues/issues/5823) **Thinking-step duration on regenerate now reflects actual processing time**: Regenerated responses no longer show the age of the conversation instead of the real thinking duration for that request.
* [#5821](https://github.com/EliteaAI/elitea_issues/issues/5821) **Switching between reasoning and non-reasoning models no longer leaves incompatible LLM settings behind**: Model-specific settings such as temperature now align more safely with the selected model behavior, preventing related sub-agent execution failures.
* [#5819](https://github.com/EliteaAI/elitea_issues/issues/5819) **`@Everyone` no longer causes inconsistent triggering or looping behavior in chat**: Mention handling now behaves more predictably so `@Everyone` does not trigger the same inconsistent LLM behavior or infinite-loop pattern.
* [#5784](https://github.com/EliteaAI/elitea_issues/issues/5784) **Configured MCP login now opens the authentication popup directly**: Users no longer need to click **Load tools** first to trigger authentication for a configured MCP.
* [#5643](https://github.com/EliteaAI/elitea_issues/issues/5643) **Nested agents with remote MCPs may not trigger the expected authorization request**: When an agent with a remote MCP is nested inside another agent or pipeline, the MCP authorization flow may fail to appear and the MCP tools may not be detected correctly.
* [#5638](https://github.com/EliteaAI/elitea_issues/issues/5638) **SharePoint toolkits in agent chat do not yet support a smart OAuth authentication flow**: Users may still need static pre-configuration because runtime OAuth prompting is not available there in the same way as for remote MCPs.
* [#5391](https://github.com/EliteaAI/elitea_issues/issues/5391) **Langfuse traces can miss the final executed pipeline or agent node**: The last executed step may be absent from the Langfuse trace even when ELITEA run details show the full execution sequence.
* [#5390](https://github.com/EliteaAI/elitea_issues/issues/5390) **Langfuse pipeline traces can still have empty top-level input and output fields**: Child spans may be present while trace-level `input` and `output` remain empty, which limits Langfuse evaluation workflows.
* [#5267](https://github.com/EliteaAI/elitea_issues/issues/5267) **Elitea MCP Tools may be unavailable when an agent is invoked as a sub-agent**: Agents that expose Elitea MCP Tools can lose those MCP tools when called from an orchestrator or other parent-agent flow.
* [#3745](https://github.com/EliteaAI/elitea_issues/issues/3745) **Stopped indexing runs from chat, agents, and pipelines no longer remain stuck in `In progress`**: Index instances created from interrupted indexing runs now move to an appropriate final state instead of remaining unresolved in the toolkit index view.
