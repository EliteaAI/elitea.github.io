**Planner** module gives agents a set of tools to create and track a step-by-step execution plan directly from chat: a titled, ordered checklist of steps that the agent updates as work progresses.

**Key features:**

* Create an execution plan with a title and an ordered list of steps
* Mark a step as in progress, then mark it completed
* Track progress with completed / in-progress / pending counts
* Resume an existing plan automatically when a conversation continues
* Delete the current plan when it is no longer needed

## Prerequisites

- An LLM that supports tool invocation
- User role with conversation edit access
- An active conversation or agent configuration
- **Planner** enabled in your chat or agent

## How to Enable Planner

The default state of the **Planner** module — on or off — [is defined in the project settings](../../menus/settings/general#default-modules).

If **Planner** is turned off by default, you can turn it on for your current conversation or agent.

### For a Conversation

1. Go to the conversation.
2. Select `+` in the chat input toolbar.
3. Select **Modules** → **Planner** in the list.
4. Toggle **Planner** on.

<img src="../../img/how-tos/chat-conversations/internal-tools/planner/euch_planner_on_chat.png" alt="Enable Planner in a Conversation" width="350" />

Once enabled, the agent gains access to the planning tools and can create or update a plan when the conversation calls for step-by-step tracking.

### For an Agent

1. Select **Agents**.
2. Select the agent to configure, or create a new agent.
3. In the **TOOLS** section, find **MODULES**.
4. Find **Planner**. Select **Show all** if you do not see it immediately.
5. Toggle **Planner** on.
6. Select **Save**.

All changes apply only to new conversations run by this agent. Existing conversations will not be affected.

## How Planner Works

When **Planner** is enabled, the agent gains access to five tools for managing a single execution plan tied to the current conversation:

| Tool | Purpose | Key Parameters |
|------|---------|----------------|
| `update_plan` | Creates a new plan, or fully replaces the current one | `title`, `steps` |
| `start_step` | Marks a step as in progress (clears any other in-progress step first) | `step_number` |
| `complete_step` | Marks a step as completed | `step_number` |
| `get_plan_status` | Returns the current plan and its progress | — |
| `delete_plan` | Deletes the current plan | — |

Each step has one of three statuses:

* `pending` — `☐` not yet started
* `in_progress` — `▶` currently being worked on
* `completed` — `☑` finished

<Note>
Only one step can be marked in progress at a time. Starting a new step automatically clears the in-progress status on any other step.
</Note>

The agent decides when to use these tools based on the conversation — there is no special command syntax or trigger phrase required.

## How to Use Planner

Planner is best suited for multi-phase work where the sequence of steps matters (deployments, onboarding checklists, review workflows) rather than for tracking many independent to-do items.

### Create a Plan

Describe the multi-step work you want tracked, or ask the agent to create a plan directly:

> Create a plan for our website deployment: run tests, build production bundle, upload to server, run smoke tests, update documentation

The agent calls `update_plan` and returns the plan as a table:

<Card title="Example Output">

**📋 Website Deployment Process**

*Progress: 0/5 completed, 0 in progress*

| # | Step |
|---|------|
| ☐ 1 | Run all unit tests |
| ☐ 2 | Build production bundle |
| ☐ 3 | Upload to server |
| ☐ 4 | Run smoke tests |
| ☐ 5 | Update documentation |

</Card>

<Warning title="Creating a Plan Replaces the Current One">
`update_plan` fully replaces any existing plan for the conversation — it does not merge new steps into the current plan. To add or change steps, ask the agent to recreate the plan with the full updated step list.
</Warning>

### Track Progress

Ask the agent to start or complete a step in natural language:

> Start working on step 1

Started step 1: Run all unit tests

<Card title="Example Output">

**📋 Website Deployment Process**

*Progress: 0/5 completed, 1 in progress*

| # | Step |
|---|------|
| ▶ 1 | Run all unit tests (in progress) |
| ☐ 2 | Build production bundle |
| ☐ 3 | Upload to server |
| ☐ 4 | Run smoke tests |
| ☐ 5 | Update documentation |

</Card>

> Mark step 1 as complete

Step 1 completed (1/5 done)

<Card title="Example Output">

**📋 Website Deployment Process**

*Progress: 1/5 completed, 0 in progress*

| # | Step |
|---|------|
| ☑ 1 | Run all unit tests ✓ |
| ☐ 2 | Build production bundle |
| ☐ 3 | Upload to server |
| ☐ 4 | Run smoke tests |
| ☐ 5 | Update documentation |

</Card>

### Check Plan Status

Ask for the current state of the plan at any time:

> What's the status of my plan?

The agent calls `get_plan_status` and returns the same table shown above, without changing anything.

### Resume an Existing Plan

When you return to a conversation that already has a plan, the agent automatically restores it and reports where it left off, for example:

```
[Resuming plan 'Website Deployment Process' - 1/5 completed, 0 in progress]
```

The agent continues from the next pending or in-progress step rather than recreating the plan.

### Delete a Plan

> Delete the current plan

The agent calls `delete_plan` and confirms deletion. This is the only way to remove a plan — it is not deleted automatically when the conversation ends.

## Plan Scope and Storage

* A plan is scoped to a single conversation; each conversation has at most one active plan
* Plans are stored outside the conversation itself, in a database table when configured, or in a local file otherwise
* Deleting a conversation or clearing its history does **not** automatically delete the associated plan; use `delete_plan` to remove it explicitly
* There is no cross-conversation plan sharing or synchronization
* Creating a new plan (`update_plan`) fully replaces any existing plan for that conversation

<Info title="Token Usage">
The full plan text is included in the tool result every time a planning tool is called, so plans with many steps use more tokens per turn.
</Info>

## Best Practices

**Plan Creation**

<Accordion title="Write Clear, Self-Contained Step Descriptions">
**Instead of:** "Fix it"

**Try:** "Fix the login authentication timeout affecting mobile users"

**Why:** Each step is shown on its own line with no additional context, so a vague description is hard to act on later.
</Accordion>

<Accordion title="Keep Plans to a Manageable Number of Steps">
* Break large efforts into 5-8 steps when possible
* Each step should be independently completable and verifiable
* Very long plans increase the token cost of every planning tool call
</Accordion>

<Accordion title="Describe the Full Sequence Upfront">
Provide all the steps you want tracked in your initial request when possible. This avoids an early `update_plan` call that would need to be replaced later once more steps become known.
</Accordion>

**Plan Management**

<Accordion title="Start a Step Before Completing It">
Use `start_step` to mark what is currently being worked on, then `complete_step` when it is finished. This keeps the in-progress indicator (`▶`) accurate if you check status mid-task or resume the conversation later.
</Accordion>

<Accordion title="Do Not Recreate a Plan That Already Exists">
Before creating a new plan, ask the agent to check the current plan status. If steps are already completed, continue from the next pending step instead of calling `update_plan` again — recreating the plan replaces it entirely and resets all progress.
</Accordion>

<Accordion title="Delete Plans You No Longer Need">
Plans are not removed automatically when a conversation ends or its history is cleared. Explicitly ask the agent to delete the plan once the work is done.
</Accordion>

**Workflow Organization**

<Accordion title="Use Planner for Multi-Phase Work, Not Single To-Dos">
**Good fit:** Deployments, onboarding sequences, review workflows, and other work where the sequence of steps matters.

**Not a good fit:** Independent, unrelated to-do items — Planner tracks one ordered plan per conversation, not a general task list.
</Accordion>

<Accordion title="One Plan per Conversation">
Keep each conversation focused on a single plan. If you need to track unrelated work, start a new conversation rather than trying to fit multiple plans into one — Planner only tracks one active plan per conversation.
</Accordion>

<Accordion title="Review Plan Status Before Ending a Session">
Ask for the plan status before wrapping up so you have a clear record of what was completed, in progress, and still pending — especially before a long pause between messages.
</Accordion>

## Troubleshooting

<Accordion title="Planner does not respond to planning requests">
**Possible causes:**

* Planner tool not enabled
* Request phrasing doesn't clearly describe multi-step work
* Model doesn't support tool invocation

**Solution:**

1. Verify that **Planner** is enabled.
2. Describe the work as a sequence of steps rather than a single request.
3. Ensure selected model supports tool invocation.
4. Refresh the page and try again.
</Accordion>

<Accordion title="Plan does not persist between messages">
**Possible causes:**

* Conversation not saved
* Browser session expired
* Network connection lost while the plan was being created or updated

**Solution:**

1. Ensure conversation is properly saved (check conversation title).
2. Verify network connection is stable.
3. Ask the agent for the plan status to confirm whether it still exists.
4. Recreate the plan if it was lost.
</Accordion>

<Accordion title="I cannot enable Planner in an agent">
**Possible causes:**

* Insufficient permissions
* Agent configuration form validation errors
* Conflicting configuration

**Solution:**

1. Ensure you have edit permissions for the agent.
2. Check for any error messages at the top of the form.
3. Ensure all required agent fields are filled.
4. Save the entire configuration form, not just the toggle.
5. Try creating a new agent version if issues persist.
</Accordion>

<Accordion title="Creating a new plan removed my previous steps">
**Possible causes:**

* `update_plan` was called again for the same conversation

**Solution:**

1. This is expected: `update_plan` always fully replaces the current plan, it does not merge in new steps.
2. To extend an existing plan, ask the agent to recreate it with the complete list of steps, including the ones already in progress or completed.
3. Check plan status before asking for a new plan if you want to confirm what exists first.
</Accordion>

<Accordion title="Planner still does not work after updating modules configuration">
**Possible causes:**

* Toggle enabled but the request isn't recognized as multi-step work
* Model context reset required
* Tool invocation blocked by settings

**Solution:**

1. Send a new message to refresh the conversation context.
2. Ask explicitly: `Create a plan with these steps: ...`.
3. Check model configuration supports tool use.
4. Disable and re-enable **Planner**.
5. Start a new conversation.
</Accordion>

<Accordion title="Plan output appears in the wrong format">
**Possible causes:**

* Model interpretation variance when relaying the tool result
* Unexpected response structure

**Solution:**

1. This is typically cosmetic; the underlying plan data is still intact.
2. Ask for plan status to see the table rendered again.
3. If persistent, report to administrator.
</Accordion>
